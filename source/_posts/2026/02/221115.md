`iperf3` 是一个常用的网络测速工具，适合排查带宽不足、延迟抖动、丢包等问题。它不像网页测速那样“只给一个结果”，而是可以精确控制测试方向、协议、时长和并发，更适合运维和开发场景。

<!-- more -->

## 前言
很多时候我们会遇到这些问题：

- 服务器下载慢，到底是出口带宽不够，还是链路质量差？
- 业务偶发超时，是应用问题，还是网络抖动导致？
- 迁移机房后，链路是否真的达到运营商承诺带宽？

这时候，`iperf3` 就非常有用。

## iperf3 是什么
`iperf3` 采用“客户端-服务端”模式：

- 一端运行服务端：负责接收或发送测试流量
- 另一端运行客户端：发起测试并输出结果

简单理解：你可以把它当成“可编程的网络体检工具”。

## 适用场景
- 机房间专线验收
- 云服务器到本地的链路测试
- 容器或虚拟机网络性能对比
- 高并发业务上线前压测网络基础能力

## 安装方式
不同系统安装命令略有区别，常见如下。

### Debian / Ubuntu
```bash
sudo apt update
sudo apt install -y iperf3
```

### CentOS / Rocky / AlmaLinux
```bash
sudo yum install -y epel-release
sudo yum install -y iperf3
```

### macOS
```bash
brew install iperf3
```

安装后可用以下命令确认版本：

```bash
iperf3 --version
```

## 最小可用示例
下面用两台机器演示（假设服务端 IP 为 `10.0.0.10`）。

### 第一步：启动服务端
在服务端执行：

```bash
iperf3 -s
```

默认监听 TCP 端口 `5201`。

### 第二步：客户端发起测试
在客户端执行：

```bash
iperf3 -c 10.0.0.10
```

输出里最重要的是：

- `sender/receiver` 吞吐量（bits/sec）
- `retransmits`（TCP 重传次数，越少越好）

## 常用命令参数（最实用）

### 1) 指定测试时长
```bash
iperf3 -c 10.0.0.10 -t 30
```
表示测试 30 秒，避免短时波动影响判断。

### 2) 增加并发连接
```bash
iperf3 -c 10.0.0.10 -P 4
```
`-P` 表示并发流数。单连接跑不满时，可以提高并发观察峰值能力。

### 3) 反向测试（服务端发回客户端）
```bash
iperf3 -c 10.0.0.10 -R
```
可以快速判断上下行是否对称。

### 4) UDP 测试（看丢包和抖动）
```bash
iperf3 -c 10.0.0.10 -u -b 100M -t 20
```
- `-u` 使用 UDP
- `-b 100M` 指定发送速率 100Mbps

UDP 场景重点看：
- `jitter`（抖动）
- `lost/total datagrams`（丢包率）

### 5) 指定端口
如果服务端用了其他端口：
```bash
iperf3 -s -p 6000
iperf3 -c 10.0.0.10 -p 6000
```

## 结果怎么解读（通用判断）
没有绝对“好坏”，但可以先按下面经验判断：

- **吞吐量低**：可能带宽瓶颈、限速策略、单流性能不足
- **TCP 重传高**：可能链路丢包、网卡/驱动问题、队列拥塞
- **UDP 丢包高**：发送速率超过链路承载，或中间设备丢包
- **抖动大**：链路不稳定，不适合实时音视频类业务

建议至少跑 3 次取中位值，不要只看一次结果。

## 常见问题排查

### 1) 连接失败 `unable to connect to server`
先检查：
- 服务端是否启动 `iperf3 -s`
- 防火墙是否放行 `5201`
- 安全组/ACL 是否允许对应端口

### 2) 跑不满带宽
可以尝试：
- 增大并发 `-P 4` 或 `-P 8`
- 延长测试时长 `-t 60`
- 分别测试正向与反向（加 `-R`）
- 排除 CPU 打满、虚拟化限速和网卡协商异常

### 3) UDP 丢包过高
先把 `-b` 降低到链路能力以内，再逐步上调，找到稳定阈值。

## 实战建议
- 尽量在业务低峰测试，减少干扰
- 记录测试时间、命令和结果，方便复现
- 跨地域测试要区分“网络问题”和“物理距离导致的时延上限”
- 与监控系统结合（带宽、丢包、CPU）一起分析更准确

## 总结
`iperf3` 上手很简单，但价值很高。只要掌握“服务端启动 + 客户端发起 + 看关键指标”这三步，就能快速定位大部分网络性能问题。

如果你刚开始使用，建议先从这三条命令练手：

```bash
iperf3 -s
iperf3 -c 10.0.0.10 -t 30
iperf3 -c 10.0.0.10 -u -b 100M -t 20
```
