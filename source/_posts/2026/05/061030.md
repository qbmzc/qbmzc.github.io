在国内网络环境下，Docker 拉取镜像经常遇到超时或无法连接的问题。通过配置代理可以有效解决。

<!-- more -->

## 代理类型说明

Docker 涉及两层的代理配置：

1. **Docker Daemon 代理**：用于 dockerd 拉取镜像时使用
2. **容器内代理**：运行容器时，容器内部进程使用的代理

## 配置 Docker Daemon 代理

Docker Daemon 负责拉取镜像、与 registry 通信，需要为其配置代理。

### 方法一：Systemd 配置（推荐）

通过 systemd override 配置 dockerd 的环境变量：

```bash
sudo mkdir -p /etc/systemd/system/docker.service.d
sudo cat > /etc/systemd/system/docker.service.d/proxy.conf << 'EOF'
[Service]
Environment="HTTP_PROXY=http://127.0.0.1:7890"
Environment="HTTPS_PROXY=http://127.0.0.1:7890"
Environment="NO_PROXY=localhost,127.0.0.1,.local,.aliyuncs.com,.docker.io"
EOF

sudo systemctl daemon-reload
sudo systemctl restart docker
```

验证代理是否生效：

```bash
sudo systemctl show --property=Environment docker
# 输出: Environment=HTTP_PROXY=http://127.0.0.1:7890 HTTPS_PROXY=http://127.0.0.1:7890 NO_PROXY=localhost,127.0.0.1,.local,.aliyuncs.com,.docker.io
```

### 方法二：daemon.json 配置

Docker 17.07+ 支持在 `daemon.json` 中配置代理：

```json
{
  "proxies": {
    "http-proxy": "http://127.0.0.1:7890",
    "https-proxy": "http://127.0.0.1:7890",
    "no-proxy": "localhost,127.0.0.1,.local,.aliyuncs.com,.docker.io"
  }
}
```

配置路径：`/etc/docker/daemon.json`，修改后重启 Docker：

```bash
sudo systemctl restart docker
```

## 配置容器内代理

容器运行时，内部进程的代理需要单独设置。

### 方法一：CLI 启动时指定

```bash
docker run -d \
  -e HTTP_PROXY=http://host.docker.internal:7890 \
  -e HTTPS_PROXY=http://host.docker.internal:7890 \
  -e NO_PROXY=localhost,127.0.0.1 \
  nginx
```

> **注意**：macOS/Windows 使用 `host.docker.internal` 访问宿主机；Linux 可用 `172.17.0.1`（默认 bridge 网关）。

### 方法二：~/.docker/config.json（客户端自动注入）

在 `~/.docker/config.json` 中配置，之后 `docker run/build` 会自动注入这些环境变量：

```json
{
  "proxies": {
    "default": {
      "httpProxy": "http://host.docker.internal:7890",
      "httpsProxy": "http://host.docker.internal:7890",
      "noProxy": "localhost,127.0.0.1"
    }
  }
}
```

> 此配置只对**从该客户端启动的容器**生效，不影响其他用户或 systemd 启动的容器。

### 方法三：docker-compose 配置

```yaml
version: '3'
services:
  app:
    image: nginx
    environment:
      - HTTP_PROXY=http://host.docker.internal:7890
      - HTTPS_PROXY=http://host.docker.internal:7890
      - NO_PROXY=localhost,127.0.0.1
```

或使用全局配置：

```yaml
x-common-env: &common-env
  HTTP_PROXY: http://host.docker.internal:7890
  HTTPS_PROXY: http://host.docker.internal:7890
  NO_PROXY: localhost,127.0.0.1

services:
  app:
    image: nginx
    environment: *common-env
  app2:
    image: alpine
    environment: *common-env
```

## Docker Build 代理配置

构建镜像时，`docker build` 也会读取 `~/.docker/config.json` 中的代理配置并注入到 `RUN` 指令中。

也可在 Dockerfile 中显式指定：

```dockerfile
FROM alpine:latest

ARG HTTP_PROXY
ARG HTTPS_PROXY
ARG NO_PROXY

ENV HTTP_PROXY=$HTTP_PROXY \
    HTTPS_PROXY=$HTTPS_PROXY \
    NO_PROXY=$NO_PROXY

RUN apk add curl
```

构建时传入：

```bash
docker build \
  --build-arg HTTP_PROXY=http://host.docker.internal:7890 \
  --build-arg HTTPS_PROXY=http://host.docker.internal:7890 \
  --build-arg NO_PROXY=localhost,127.0.0.1 \
  -t myapp .
```

## 各场景配置汇总

| 场景 | 配置位置 | 生效范围 |
|------|----------|----------|
| Daemon 拉取镜像 | `/etc/systemd/system/docker.service.d/proxy.conf` 或 `/etc/docker/daemon.json` | dockerd 进程 |
| 容器运行时 | `~/.docker/config.json` 或 docker-compose environment | 容器内进程 |
| Docker Build | `~/.docker/config.json` 或 `--build-arg` | Dockerfile RUN 指令 |
| Docker Compose | `environment` 字段 | compose 管理的容器 |

## 常见问题

### 1. 代理地址怎么选？

| 平台 | 宿主机地址 |
|------|-----------|
| macOS / Docker Desktop | `host.docker.internal` |
| Windows | `host.docker.internal` |
| Linux（默认 bridge） | `172.17.0.1` |
| Linux（host 网络） | `127.0.0.1` |
| Linux（自定义网络） | 宿主机实际 IP |

### 2. 配置后拉取还是超时？

检查代理服务是否监听在正确地址：

```bash
# 确认代理端口已监听
ss -tlnp | grep 7890

# 测试代理连通性
curl -x http://127.0.0.1:7890 -I https://google.com
```

### 3. NO_PROXY 配置建议

建议将以下地址加入 NO_PROXY：

- `localhost`、`127.0.0.1`
- 内网 registry 地址（如 `registry.company.com`）
- 国内镜像加速地址（如 `.aliyuncs.com`、`.mirror.aliyuncs.com`）
- Docker Hub 只读镜像（如 `.docker.io`）
