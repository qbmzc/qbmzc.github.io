> 让 AI Agent 在远程服务器持续工作：电脑负责开发，手机负责监控和接管。告别 SSH 断线后任务中断的困扰。

**关键词：** Herdr、Whip、Android、Codex、OpenCode、SSH、WireGuard、AI Agent、远程开发

## 一、前言

最近一直在尝试将 AI Coding Agent 融入日常开发工作流。

目前常用的工具包括 Codex 和 OpenCode。它们已经能够完成代码生成、重构、测试、问题排查等任务，但在多设备协作方面，我一直有一个需求：

**能不能在 Mac 上启动 AI 编程任务，离开电脑后通过 Android 手机继续查看和操作，回到电脑时又能直接接着工作？**

传统 SSH 虽然能够实现远程操作，但并没有解决多 Agent 管理和移动端操作体验的问题。

经过研究，我选择了以下组合：

- **Herdr：** 管理远程终端和 AI Coding Agent，提供持久化会话。
    
- **Whip：** 专为 Herdr 设计的 Android/iOS SSH 客户端，提供原生 Agent 管理界面。
    
- **SSH：** 连接电脑、手机与远程开发服务器。
    
- **WireGuard：** 实现手机从外网安全访问内网服务器。
    

最终希望实现这样的效果：

1. 在 Mac 上启动 Codex 编程任务。
    
2. AI Agent 在远程服务器持续执行。
    
3. 关闭 Mac 的 Herdr 客户端，任务依旧运行。
    
4. 手机打开 Whip，查看 Agent 状态、阅读回复。
    
5. Agent 需要输入时，直接在手机上继续对话。
    
6. 返回 Mac，重新连接原来的任务和终端。
    

重点是：**两个设备操作的是同一个远程 Herdr 会话，而不是各自运行一套 Agent。**

## 二、整体架构设计

采用集中式运行架构，所有开发环境、代码和 Agent 都运行在远程 Linux 服务器上。

```
┌─────────────────────┐
│    Mac 开发电脑       │
│                     │
│   Herdr CLI / TUI   │
│   herdr --remote    │
└──────────┬──────────┘
           │
           │ SSH
           │
           ▼
┌───────────────────────────┐
│      远程 Linux 服务器      │
│                           │
│       Herdr Server        │
│             │             │
│       Herdr Session       │
│             │             │
│     ┌───────┴────────┐    │
│     │                │    │
│  Workspace A     Workspace B
│     │                │    │
│   Codex           OpenCode │
│   Shell           Shell    │
│     │                │    │
│     └────────────────┘    │
│                           │
│     项目代码 / Git / 环境   │
└─────────────▲─────────────┘
              │
              │ SSH
              │
       ┌──────┴───────┐
       │ Android 手机  │
       │               │
       │ Whip App      │
       │ WireGuard     │
       └───────────────┘
```

这里需要区分 Herdr 的 Server 和 Client。

Herdr Server 运行在远程服务器，持有终端和 Agent 的执行状态。Mac 本地的 Herdr 只是客户端，通过 SSH 连接远程 Server。

Whip 也是客户端，只不过它不是简单地将 Herdr 的终端界面搬到手机上，而是利用 Herdr 的接口，将 Agent 状态、会话管理和交互操作呈现为原生移动端界面。

这套架构的最大优势是：**客户端可以断开，执行环境不需要跟着断开。**

不过，持久化不等于永久执行。服务器宕机、Agent 自身退出、会话被停止等情况仍会影响任务运行。

## 三、环境准备

本文使用以下示例环境：

| 组件       | 环境                      |
| -------- | ----------------------- |
| 远程服务器    | Arch Linux              |
| 桌面客户端    | macOS                   |
| 手机客户端    | Android + Whip          |
| Agent    | Codex / OpenCode        |
| 远程连接     | OpenSSH                 |
| 外网访问     | WireGuard/tailscale（可选） |
| 远程地址     | 192.168.1.100（示例）       |
| Linux 用户 | dev（示例）                 |

前提条件：

- 远程服务器已经安装并配置好 Codex 或 OpenCode。
    
- Linux 服务器的 SSH 服务正常运行。
    
- Mac 和 Android 都能够通过网络访问服务器。
    
- 远程服务器上的 Herdr 版本与 Whip 支持的协议兼容。
    

本文假设 AI Agent 原本就在远程服务器运行，不涉及将本地项目迁移到远程服务器。

## 四、部署远程 Herdr Server

### 4.1 安装 Herdr

SSH 登录远程服务器：

```
ssh dev@192.168.1.100
```

Linux 可使用 Herdr 官方安装脚本：

```
curl -fsSL https://herdr.dev/install.sh | sh
```

执行前建议先检查脚本来源及内容。

验证安装：

```
herdr --version
```

如果服务器已经安装 Herdr，可以跳过安装步骤。

### 4.2 启动 Herdr

进入项目目录：

```
cd /workspace/my-project
```

启动：

```
herdr
```

Herdr 会自动启动或附加到默认的后台会话。通常不需要额外运行 `herdr server`。

可以在 Herdr 中创建工作区，并在终端 Pane 内执行：

```
codex
```

或者：

```
opencode
```

此时 Codex/OpenCode 运行在远程服务器，而不是 Mac 或手机。

### 4.3 检查运行状态

在服务器另一个终端执行：

```
herdr status server
```

查看现有会话：

```
herdr session list
```

默认会话名为：

```
default
```

如果准备使用专门的开发会话，可以通过以下方式启动：

```
herdr --session development
```

后续其他客户端也需要指定 `development`，才能连接到同一命名会话。

### 4.4 保持 Agent 持续运行

Herdr 的一个重要特性是客户端与 Server 分离。

在 Herdr 中按：

```
Ctrl+B
Q
```

即按下 `Ctrl+B` 后再按 `Q`，可以从当前客户端分离。

分离后，后台会话和正在运行的 Pane 不会因为客户端退出而被主动停止。

需要注意的是，以下命令与分离不同：

```
herdr server stop
```

它会停止服务器会话，不应该被当作正常退出客户端的方法。

## 五、Mac 使用 Herdr 连接远程服务器

### 5.1 安装 Mac 客户端

如果 Mac 尚未安装 Herdr，可以通过 Homebrew：

```
brew install herdr
```

验证：

```
herdr --version
```

### 5.2 配置 SSH 别名

编辑 Mac 本地 SSH 配置：

```
vim ~/.ssh/config
```

添加：

```
Host devbox
    HostName 192.168.1.100
    User dev
    Port 22
    IdentityFile ~/.ssh/id_ed25519
    ServerAliveInterval 30
    ServerAliveCountMax 3
```

其中：

- `devbox`：自定义服务器别名。
    
- `HostName`：远程服务器 IP 或域名。
    
- `User`：远程 Linux 用户。
    
- `IdentityFile`：SSH 私钥路径。
    
- `ServerAliveInterval`：SSH 保活间隔。
    
- `ServerAliveCountMax`：连续无响应次数阈值。
    

先测试：

```
ssh devbox
```

正常登录后，退出 SSH，再在 Mac 本地启动 Herdr：

```
herdr --remote devbox
```

如果使用命名会话：

```
herdr --remote devbox --session development
```

**特别注意：不要先 SSH 登录服务器再执行** `**herdr --remote devbox**`**。**

这里希望运行的是 Mac 本地的 Herdr Client，所以命令应该在 Mac 本地终端执行。

### 5.3 为什么推荐 `herdr --remote`

Herdr 提供两种常见的远程工作方式。

第一种：

```
ssh devbox
herdr
```

此时 Herdr 的客户端和服务端都在远程 Linux 上运行，Mac 只是普通 SSH 终端。

第二种：

```
herdr --remote devbox
```

此时 Mac 负责 Herdr 界面的渲染，而终端及 Agent 仍保留在远程 Linux 服务器。

第二种方式更适合桌面日常开发，因为能够使用 Mac 本地的界面配置和部分桌面集成功能，例如图片剪贴板桥接。

两种方式都可以访问远程持久化会话。本文采用第二种。

## 六、Android 安装 Whip

Whip 是一款面向 Herdr 的原生移动端客户端。

它与普通 SSH 工具的主要区别是：

**Whip 不只是显示终端，还能直接管理 Herdr 中的 Agent、Workspace 和 Pane。**

### 6.1 下载和安装

项目地址：

[https://github.com/kosumic/whip](https://github.com/kosumic/whip)

GitHub Releases：

[https://github.com/kosumic/whip/releases](https://github.com/kosumic/whip/releases)

官方提供 Google Play Early Access 渠道，也提供经过签名的 Android ARM64 APK。

不便使用 Google Play 时，可以进入 Releases 下载：

```
whip-arm64.apk
```

建议同时下载发布页提供的 SHA-256 校验文件，确认安装包完整性。

Whip 支持 Android 7.0 及以上系统，但当前直接分发的 APK 主要面向 ARM64 设备。

由于 Whip 仍处于持续开发阶段，安装前应查看最新版本说明和协议兼容性要求。

### 6.2 配置远程 SSH Host

安装完成后，在 Android 手机打开 Whip。

选择添加主机（Add Host），填写连接信息。

示例：

|参数|配置|
|---|---|
|Host|192.168.1.100|
|Port|22|
|Username|dev|
|Authentication|SSH Private Key|
|Command|herdr|
|Session|default|

这里有两个关键配置。

**Command**

默认保持：

```
herdr
```

Whip 会通过 SSH 调用服务器上的 Herdr。

如果服务器使用了特殊安装路径，非交互 SSH 环境中找不到 Herdr，可以填写可执行文件绝对路径，例如：

```
/home/dev/.local/bin/herdr
```

具体路径使用服务器上的实际安装路径。

**Session**

必须与 Mac 所使用的远程 Herdr 会话一致。

例如 Mac 使用：

```
herdr --remote devbox --session development
```

那么 Whip 的 Session 应填写：

```
development
```

如果双方都使用默认会话，则填写：

```
default
```

### 6.3 配置 SSH 密钥

推荐使用 SSH 密钥认证，避免每次输入密码。

Whip 支持导入已有密钥，也支持生成新的 Ed25519 密钥。

为了减少私钥在多设备之间复制，建议直接在 Whip 内生成独立密钥。

将 Whip 显示的公钥添加到服务器对应账号的：

```
~/.ssh/authorized_keys
```

在服务器上确认权限：

```
chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys
```

如果手动复制公钥，也可以使用以下方式追加：

```
printf '%s\n' '手机生成的SSH公钥' >> ~/.ssh/authorized_keys
```

注意替换为真实的公钥内容，不要把私钥复制到服务器。

首次连接时，Whip 会显示服务器 SSH Host Key 指纹。

建议在服务器上通过可信渠道核对：

```
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

核对一致后，再在 Whip 中信任该服务器。

### 6.4 连接 Herdr

完成配置后，点击连接。

如果远程服务器、SSH 和 Herdr 都正常，Whip 就可以读取对应 Herdr 会话的状态。

在 Whip 内，主要会用到以下功能：

**Hosts**

查看服务器连接状态，管理多个 SSH 主机。

**Herd**

聚合展示 Agent 的工作状态，例如正在执行、等待输入、已完成等。

**Terminal**

访问现有 Pane 的终端，必要时直接执行命令。

**Chat View**

对于支持的 Codex 和 OpenCode 活动 Pane，可以通过原生聊天界面阅读 Agent 对话和继续发送输入，而不必始终操作完整终端。

Whip 也支持通过 SFTP 浏览和传输远程文件。

## 七、Mac 与 Android 如何无缝协作？

完成上述配置后，正式开始体验跨设备接力。

### 场景一：电脑启动，手机查看

首先在 Mac 上执行：

```
herdr --remote devbox
```

进入 Herdr 的项目工作区，启动 Codex：

```
codex
```

向 Agent 发送一个任务，例如：

```
请检查当前项目的接口层代码，
分析潜在的性能问题，
修复可以确认的问题，
并运行相关测试。
```

此时任务在远程 Linux 服务器执行。

接下来从 Mac 的 Herdr 中分离：

```
Ctrl+B → Q
```

打开 Android 手机上的 Whip，连接同一主机和 Session。

在 Herd 界面中找到对应 Codex Agent，即可查看其工作状态。

如果它已经完成任务，可以在手机上查看回复。如果 Agent 需要进一步输入，可以进入相关 Pane 或 Chat View 继续操作。

### 场景二：手机继续给 Agent 下达任务

假设 Codex 已完成第一轮代码检查。

在 Whip 内找到对应的 Agent，进入支持的 Chat View 或终端，继续发送：

```
继续执行单元测试，
分析失败用例，
修复后重新测试，
最后总结代码修改内容。
```

Agent 继续在远程服务器运行。

手机本身无需安装 Codex，也不需要存储整个项目代码。

### 场景三：回到 Mac 接着开发

回到 Mac，执行：

```
herdr --remote devbox
```

或者使用原来的命名会话：

```
herdr --remote devbox --session development
```

重新进入对应 Workspace 和 Pane，就能查看此前 Agent 的执行结果，并继续交互。

这里实现的是服务端会话接力，而不是 Mac 与 Android 的界面逐像素同步。

两个客户端的界面布局、当前选中项目和滚动位置，不一定完全一致。

但只要连接的是同一个服务端会话，终端和 Agent 的工作状态就不会因为换设备而重新创建。

### 场景四：网络中断

例如手机从 Wi-Fi 切换为 5G，SSH 连接可能短暂中断。

Whip 支持在应用恢复或网络变化后重新建立控制连接，尽量恢复对已有终端的访问。

不过需要区分三个概念：

- 网络连接恢复：客户端重新连接服务器。
    
- Herdr 会话持续：远程终端不因客户端断线而主动结束。
    
- Agent 任务成功：仍取决于 Agent 自身、远程进程和服务器是否正常。
    

即使 Agent 的会话持续存在，也不能保证每次编程任务都执行成功。

## 八、通过 WireGuard 实现外网安全访问

在局域网内，可以直接使用服务器的私有 IP 地址。

但如果手机离开家庭或办公网络，就需要解决远程网络访问问题。

这里我更推荐使用已经部署好的 WireGuard，而不是直接将 SSH 端口暴露到公网。

网络结构如下：

```
Android 手机
    │
    │ WireGuard 加密隧道
    │
    ▼
WireGuard 服务端
    │
    │ 内网路由
    │
    ▼
Linux 开发服务器
    │
    ├── SSH
    └── Herdr Server
```

操作步骤：

1. 在 Android 手机安装 WireGuard。
    
2. 导入已有的 WireGuard 客户端配置。
    
3. 确认隧道连接正常。
    
4. 验证手机能够访问 Linux 服务器的 SSH 端口。
    
5. 在 Whip 中填写 WireGuard 可达的服务器 IP。
    

例如服务器通过 VPN 可访问的地址为：

```
10.10.0.2
```

则在 Whip 中设置：

```
Host: 10.10.0.2
Port: 22
```

如果目标服务器与 WireGuard 服务端不是同一台机器，还需要确保路由、IP 转发以及防火墙规则正确。

注意：WireGuard 的 `AllowedIPs` 应包含目标服务器地址或对应网段，同时服务端需要具备返回客户端的网络路径。

不建议为了方便而直接开放 Herdr 的本地 API Socket。Whip 本来就通过 SSH 访问这些接口，无需额外暴露服务。

## 九、常见问题排查

### 9.1 Whip SSH 连接成功，但找不到 Herdr

首先在服务器执行：

```
command -v herdr
```

查看实际路径。

再从 Mac 测试非交互 SSH：

```
ssh devbox 'herdr status server --json'
```

如果提示：

```
herdr: command not found
```

说明非交互 SSH 环境可能没有包含 Herdr 的安装目录。

解决方法是在 Whip 的 Command 字段中填写实际绝对路径。

例如：

```
/home/dev/.local/bin/herdr
```

### 9.2 Mac 能看到 Agent，Whip 却看不到

优先检查以下因素：

1. 是否连接了同一台服务器。
    
2. 是否使用同一个 Linux 用户。
    
3. Session 名称是否一致。
    
4. Herdr 是否正常运行。
    
5. Whip 是否支持当前 Herdr 的协议版本。
    

特别是 Session 很容易配置不一致。

例如 Mac 连接 `development`，手机却连接 `default`，那么看到的就是不同会话。

### 9.3 手机端提示 Herdr 协议不兼容

Whip 并非 Herdr 官方项目，两者会独立更新。

不同版本之间可能存在协议兼容性限制。

遇到此类错误时，先查看：

```
herdr --version
```

再检查 Whip 的 About 页面显示的协议版本，以及其 GitHub README 的兼容说明。

不要直接假设升级到最新 Herdr 后旧版 Whip 就一定能够连接。

### 9.4 SSH 断开会停止 Agent 吗？

通常不会。

前提是 Agent 运行在 Herdr 管理的远程持久化 Pane 中，而不是在 Herdr 之外启动的普通 SSH 前台进程。

如果 Agent 是直接运行在普通 SSH Shell 内，那么连接中断仍可能导致进程退出。

因此，**关键不是使用了 SSH，而是让任务真正运行在 Herdr 管理的会话内。**

### 9.5 Whip 能否不打开就一直通知 Agent 状态？

Whip 支持 Agent 阻塞、完成等状态的本地提醒，以及可配置的通知和语音功能。

但不能将它简单理解为全天候云端推送服务。

通知是否及时取决于应用连接状态、后台运行权限、Android 电池优化策略等因素。

Whip 没有要求为此额外部署一个公网通知网关。

对于希望长期稳定监控任务的用户，仍应通过实际设备验证后台提醒行为。

## 十、安全建议

因为 Whip 可以直接操作远程终端和 AI Agent，所以必须把它视为具有服务器操作权限的客户端。

推荐的安全配置：

- 使用 WireGuard 等私有网络访问服务器。
    
- 为手机生成单独的 SSH 密钥，便于单独吊销权限。
    
- 在首次连接时核对 SSH 主机指纹。
    
- 不要将 SSH 私钥直接复制进项目仓库。
    
- 避免让日常 Agent 使用 root 权限。
    
- 对重要项目使用 Git 版本控制。
    
- 为高风险操作保留人工确认。
    
- 确保服务器有必要的备份和资源限制。
    

还需要注意，AI Agent 不一定只会修改代码。

如果 Agent 可以执行 Shell 命令，那么误操作可能影响文件、运行服务和其他数据。

移动端提供的是更方便的控制入口，并没有消除 Agent 本身的执行风险。

## 十一、这套方案的优势与不足

### 优势

**1. 真正的多设备任务接力**

Mac 和 Android 操作同一个远程运行环境，不需要重新创建 AI Agent 会话。

**2. 远程资源集中管理**

项目代码、依赖环境、API 凭据和 Agent 都位于远程服务器，终端设备只负责交互。

**3. 不需要额外部署 Web 管理平台**

Herdr 已具备持久化终端服务，Whip 直接通过 SSH 与其交互。

**4. 充分利用现有设备**

已有的 Linux 服务器、Mac 和 NAS 网络环境都能继续使用。

**5. 手机端操作更自然**

Whip 提供原生 Agent 管理、聊天、终端和文件浏览能力，比单纯在手机 SSH 中使用 TUI 更方便。

### 不足

**1. 依赖远程服务器稳定性**

服务器离线、磁盘不足或 Agent 进程异常，依然会影响任务。

**2. 移动端与桌面端不是完全同步的 UI**

共享的是服务器会话，而不是所有客户端界面状态。

**3. Whip 与 Herdr 有兼容性要求**

升级时需要关注接口协议变化。

**4. 手机后台通知存在系统限制**

不能保证所有 Android 设备都能够始终维持连接或及时提醒。

## 十二、总结

这次部署的核心思想其实非常简单：

**让 AI Agent 留在服务器，让客户端自由切换。**

以前的工作方式是：

```
打开电脑
    ↓
连接服务器
    ↓
启动 Agent
    ↓
一直守着终端
    ↓
查看结果
```

现在可以变成：

```
Mac 创建任务
    ↓
远程 Herdr 持续执行
    ↓
Android Whip 查看状态
    ↓
手机补充指令
    ↓
Mac 接力继续开发
```

Herdr 解决的是 Agent 终端管理和会话持久化问题，Whip 解决的是移动端交互问题，WireGuard 则提供安全的网络访问路径。

对于已经具备 Linux 服务器、经常使用 Codex/OpenCode、又希望充分利用碎片时间管理 AI 编程任务的开发者而言，这是一套值得实践的轻量级方案。

它没有引入额外的 Agent 调度平台，也没有要求每个客户端安装 Docker 或重新部署项目。

所有工具围绕一个远程开发环境协作，既减少了重复配置，也降低了日常管理成本。
