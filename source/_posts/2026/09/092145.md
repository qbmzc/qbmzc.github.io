Edge/Chrome 播放 4K60 H.264 视频黑屏只有声音，关闭硬件加速后正常：AMD 显卡驱动问题排查

<!-- more -->



最近遇到一个比较有意思的视频播放问题。

手机拍摄的视频上传到 NAS 后，在浏览器中播放时出现：

> **视频黑屏，但是声音正常播放。**

同一个视频使用 VLC、PotPlayer 等本地播放器却可以正常播放。

一开始很容易怀疑是视频损坏、浏览器不支持编码格式，或者 MP4 封装有问题。但最终排查发现，真正的问题出在：

> **AMD 显卡驱动与浏览器硬件视频解码链路的兼容性。**

本文记录一下完整排查过程。

---

## 一、视频基本信息

视频来自 Xiaomi 13，拍摄规格为 4K 60FPS。

使用 ExifTool 查看部分信息：

```text
AndroidManufacturer: Xiaomi
AndroidModel: 2211133C
XiaomiProductMarketname: Xiaomi 13

ImageSize: 3840x2160
VideoFrameRate: 59.979
AvgBitrate: 62.7 Mbps

CompressorID: avc1
AudioFormat: mp4a

ColorPrimaries: BT.709
TransferCharacteristics: BT.709
MatrixCoefficients: BT.709

Rotation: 90
```

从这里可以看到：

```text
分辨率：3840 × 2160
帧率：约 60 FPS
平均码率：约 62.7 Mbps
视频编码：H.264 / AVC
音频编码：AAC
```

MP4、H.264 和 AAC 理论上都属于浏览器支持非常成熟的格式。

但浏览器播放时仍然只有声音，没有画面。

---

# 二、进一步使用 ffprobe 检查编码参数

ExifTool 没有完整显示 H.264 Profile、Level 和像素格式，所以进一步使用 ffprobe：

```powershell
ffprobe -v error `
-select_streams v:0 `
-show_entries stream=codec_name,profile,level,pix_fmt,width,height,r_frame_rate,avg_frame_rate,bit_rate `
-of default=noprint_wrappers=1 `
VID_20260908_224700.mp4
```

得到：

```text
codec_name=h264
profile=High
width=3840
height=2160
pix_fmt=yuv420p
level=52
r_frame_rate=60/1
avg_frame_rate=55620000/927329
bit_rate=62573269
```

整理之后就是：

```text
Codec       : H.264
Profile     : High
Level       : 5.2
Resolution  : 3840 × 2160
Frame Rate  : 60 FPS
Pixel Format: yuv420p
Bitrate     : 62.6 Mbps
```

其中最值得关注的是：

```text
H.264 High Profile
Level 5.2
4K
60 FPS
62 Mbps
```

这已经属于规格比较高的 H.264 视频。

---

# 三、为什么声音正常，视频却黑屏？

这里其实是一个重要线索。

音频编码是：

```text
AAC / mp4a
```

浏览器可以正常解码，因此声音正常。

但视频是：

```text
H.264 High Profile Level 5.2
3840×2160 @ 60FPS
```

浏览器播放视频时，如果开启了硬件加速，一般会优先调用 GPU 的视频解码能力。

大致链路可以理解为：

```text
MP4
  ↓
Chromium / Edge
  ↓
Windows Media Foundation / D3D11
  ↓
GPU Hardware Video Decoder
  ↓
画面输出
```

如果 GPU 驱动在解码这个视频时出现兼容问题，就可能出现一种比较特殊的状态：

```text
音频解码成功
+
视频解码失败
=
有声音但是黑屏
```

所以“能听到声音”并不能说明整个视频播放链路都是正常的。

---

# 四、最关键的测试：关闭浏览器硬件加速

在 Edge 中进入：

```text
edge://settings/system
```

关闭：

```text
可用时使用图形加速
```

然后彻底退出 Edge，再重新打开。

重新播放原视频。

结果：

> **视频立刻可以正常播放。**

到这一步，其实问题已经基本锁定。

关闭硬件加速后，浏览器不再依赖原来的 GPU 视频硬件解码路径，而是使用软件解码或其他 fallback 路径。

也就是说：

```text
硬件加速开启
    ↓
黑屏 + 有声音

硬件加速关闭
    ↓
正常播放
```

这说明：

> 视频文件本身基本没有问题。

问题更可能存在于：

```text
浏览器
↓
D3D11 / DXVA / Media Foundation
↓
AMD GPU 驱动
↓
硬件视频解码
```

这一整条链路。

---

# 五、电脑硬件环境

这台电脑是：

```text
HP 战66 AMD 锐龙版
```

处理器：

```text
AMD Ryzen 7 PRO 4750U with Radeon Graphics
```

显卡：

```text
AMD Radeon(TM) Graphics
```

当时 Windows 中显示的驱动信息：

```text
驱动程序版本：31.0.21912.2004
驱动程序日期：2024/06/18
DirectX：12
```

Ryzen 7 PRO 4750U 属于 Renoir 平台。

它本身具备 H.264 硬件视频解码能力，因此 4K60 H.264 并不是一个明显超出硬件能力范围的视频。

这时问题的重点就进一步从：

```text
GPU 能不能解
```

变成了：

```text
当前驱动能不能正常解
```

---

# 六、发现 AMD Adrenalin 驱动环境异常

尝试打开 AMD Software: Adrenalin Edition 时，又出现了一个非常关键的提示：

```text
The version of AMD Software that you have launched
is not compatible with your currently installed AMD graphics driver.
```

即 AMD 的：

```text
PA-300
```

错误。

简单理解就是：

```text
AMD Software 版本
        ↓
和
        ↓
当前实际安装的 AMD 显卡驱动

不匹配
```

例如可能出现：

```text
AMD Adrenalin：版本 A

Windows 当前显卡驱动：版本 B
```

这种状态经常发生在：

```text
Windows Update 自动替换显卡驱动
```

之后。

驱动被 Windows 更新成另外一个版本，但原来的 AMD Software 控制面板没有同步更新，于是形成版本错配。

---

# 七、最终解决方案：重新整理 AMD 驱动环境

由于同时出现了两个现象：

```text
1. 浏览器开启 GPU 加速后 4K60 H.264 黑屏

2. AMD Software 报 PA-300
```

因此没有继续折腾浏览器，而是直接处理显卡驱动。

处理思路为：

```text
AMD Cleanup Utility
        ↓
清理现有 AMD 驱动
        ↓
重启
        ↓
重新安装匹配的 AMD 显卡驱动
        ↓
重启
        ↓
重新开启浏览器硬件加速
```

对于 HP 战66 这种品牌笔记本，一般有两个驱动来源：

```text
HP OEM 驱动

或者

AMD 官方 Adrenalin 驱动
```

原则上优先考虑 HP 针对具体机型验证过的 OEM 驱动。

但是如果 HP 提供的驱动版本非常老，或者已经出现明显的视频解码兼容问题，也可以考虑 AMD 官方提供的新版本驱动。

重新整理并安装正确驱动后，问题得到解决。

最终：

```text
Edge 硬件加速：开启

4K60 H.264：正常播放

无需转码
```

---

# 八、为什么不建议第一时间转码？

一开始其实很容易想到一个解决方案：

把：

```text
3840×2160
60FPS
H.264 High Level 5.2
62Mbps
```

转成：

```text
1920×1080
H.264
8~12Mbps
```

这样确实很可能可以播放。

但是这里存在一个问题：

> **转码只是绕过了问题，并没有找到问题。**

因为原视频实际上是标准：

```text
H.264
yuv420p
MP4
AAC
```

并不存在非常奇怪的编码格式。

而且设备本身也具有对应的硬件解码能力。

如果只是为了浏览器兼容而把大量手机 4K 视频全部转码，会产生几个额外问题：

```text
画质损失
大量 CPU/GPU 消耗
NAS 转码压力
额外存储空间
等待时间
```

所以如果设备理论上具备解码能力，更合理的方式应该是先排查：

```text
浏览器
显卡驱动
硬件加速
视频解码器
```

而不是立即修改源视频。

---

# 九、遇到类似问题可以怎么快速判断？

以后如果再遇到：

> MP4 浏览器播放黑屏，但是有声音

可以按下面顺序快速检查：

1. 用 `ffprobe` 查看视频编码、Profile、Level、分辨率、帧率和像素格式。
2. 用 VLC / PotPlayer 测试源文件，排除视频本身损坏。
3. 关闭 Chrome / Edge 硬件加速测试。
4. 如果关闭硬件加速恢复正常，重点检查 GPU 驱动和硬件解码。
5. 查看 `edge://gpu` 判断 Video Decode 是否启用了硬件加速。
6. 查看 `edge://media-internals` 判断浏览器实际使用的 Video Decoder。
7. 更新或重新安装显卡驱动。
8. 最后才考虑视频转码。

其中一个非常有效的判断方法就是：

```text
开启硬件加速 → 黑屏

关闭硬件加速 → 正常
```

如果出现这个现象，通常就不要继续怀疑 MP4 文件了。

应该优先调查 GPU 硬解。

---

# 十、总结

整个问题最终可以概括成一句话：

> **Xiaomi 13 拍摄的 H.264 High Profile Level 5.2、4K60 视频，在 Edge 中播放时，由于 AMD 显卡驱动硬件视频解码链路异常导致黑屏；关闭硬件加速后软件解码正常，最终通过修复和更新 AMD 驱动解决，无需对原视频进行转码。**

这次排查中几个比较值得记录的经验是：

```text
有声音不代表视频文件正常播放
浏览器支持 H.264 ≠ 所有 H.264 都走同一条解码路径
播放器能播放 ≠ 浏览器 GPU 硬解一定能播放
关闭浏览器硬件加速是非常有效的诊断手段
PA-300 往往意味着 AMD Software 和驱动版本已经不匹配
品牌机 OEM 驱动、Windows Update 和 AMD 官方驱动可能互相覆盖
```

最终问题不是：

```text
H.264 不支持
```

也不是：

```text
4K60 太高
```

更准确地说是：

```text
AMD GPU
+
驱动版本/状态异常
+
Chromium 硬件视频解码
=
4K60 H.264 黑屏
```

修复驱动之后，原视频可以继续保持 **4K60、62Mbps 原始质量**，浏览器也能够正常使用硬件加速播放。
