## 问题描述

在使用 Druid 连接池时，应用运行一段时间后出现数据库通信异常，导致业务请求失败。

## 错误信息

```log
c.a.d.p.DruidPooledStatement : CommunicationsException, druid version 1.1.14, 
jdbcUrl : jdbc:mysql://ce-mysql01.hengrui.com:3306/fs?useUnicode=true&characterEncoding=utf8&allowMultiQueries=true&useSSL=false, 
testWhileIdle true, idle millis 894082, minIdle 20, poolingCount 1, 
timeBetweenEvictionRunsMillis 900000, lastValidIdleMillis 894082, 
driver com.mysql.jdbc.Driver, 
exceptionSorter com.alibaba.druid.pool.vendor.MySqlExceptionSorter
```

## 问题分析

### 根本原因

连接池中的连接因长时间空闲（约 894 秒，接近 15 分钟）被 MySQL 服务器主动断开，而 Druid 连接池未能及时检测并清理这些失效连接。

### 关键配置问题

原配置中存在以下问题：

```properties
# 空闲连接检测间隔过长（15 分钟）
spring.datasource.druid.time-between-eviction-runs-millis = 900000
```

**问题点：**
- MySQL 默认的 `wait_timeout` 通常为 8 小时（28800 秒）
- 但在某些网络环境或负载均衡器配置下，空闲连接可能在更短时间内被断开
- 15 分钟的检测间隔过长，导致失效连接未被及时清理

## 解决方案

### 优化后的完整配置

```properties
# 数据源基础配置
spring.datasource.url = jdbc:mysql://ce-mysql01.hengrui.com:3306/fs?useUnicode=true&characterEncoding=UTF-8&allowMultiQueries=true&useSSL=false&autoReconnect=true&connectTimeout=5000&socketTimeout=30000
spring.datasource.type = com.alibaba.druid.pool.DruidDataSource

# 连接池大小配置
spring.datasource.druid.max-active = 200
spring.datasource.druid.min-idle = 20
spring.datasource.druid.initial-size = 20

# 连接有效性检测配置
spring.datasource.druid.validation-query = SELECT 1
spring.datasource.druid.test-on-borrow = false
spring.datasource.druid.test-on-return = false
spring.datasource.druid.test-while-idle = true

# 空闲连接回收配置（关键优化点）
spring.datasource.druid.max-evictable-idle-time-millis = 800000
spring.datasource.druid.min-evictable-idle-time-millis = 600000
spring.datasource.druid.time-between-eviction-runs-millis = 60000
```

### 配置说明

| 配置项 | 值 | 说明 |
|--------|-----|------|
| `autoReconnect` | true | 连接断开时自动重连（注意：MySQL 8.0+ 已废弃） |
| `connectTimeout` | 5000 | 连接超时时间（5 秒） |
| `socketTimeout` | 30000 | Socket 读取超时时间（30 秒） |
| `test-while-idle` | true | 空闲时检测连接有效性 |
| `time-between-eviction-runs-millis` | 60000 | 每 60 秒检测一次空闲连接（从 15 分钟优化为 1 分钟） |
| `min-evictable-idle-time-millis` | 600000 | 连接空闲 10 分钟后可被回收 |
| `max-evictable-idle-time-millis` | 800000 | 连接空闲 13.3 分钟后强制回收 |

### 核心优化点

1. **缩短检测间隔**：从 15 分钟缩短到 1 分钟，及时发现并清理失效连接
2. **添加超时配置**：设置连接和读取超时，避免长时间等待
3. **启用空闲检测**：通过 `test-while-idle` 配合 `validation-query` 主动检测连接状态

## 最佳实践建议

### 1. 关于 autoReconnect

`autoReconnect=true` 在 MySQL Connector/J 8.0+ 版本中已被废弃，不推荐使用。更好的做法是：
- 依赖连接池的健康检查机制
- 合理配置连接回收策略

### 2. 检测间隔设置原则

```
time-between-eviction-runs-millis < MySQL wait_timeout / 2
```

建议设置为 1-5 分钟之间，平衡性能和可靠性。

### 3. 生产环境推荐配置

```properties
# 更激进的检测策略（适用于高可用场景）
spring.datasource.druid.time-between-eviction-runs-millis = 30000
spring.datasource.druid.min-evictable-idle-time-millis = 300000
spring.datasource.druid.max-evictable-idle-time-millis = 600000

# 可选：启用连接泄漏检测
spring.datasource.druid.remove-abandoned = true
spring.datasource.druid.remove-abandoned-timeout = 180
spring.datasource.druid.log-abandoned = true
```

### 4. 监控建议

启用 Druid 监控页面，实时观察连接池状态：

```properties
# 启用 Druid 监控
spring.datasource.druid.stat-view-servlet.enabled = true
spring.datasource.druid.stat-view-servlet.url-pattern = /druid/*
spring.datasource.druid.stat-view-servlet.reset-enable = false
```

访问 `http://your-app/druid/` 查看连接池详细信息。

## 总结

通过优化 Druid 连接池的空闲连接检测策略，将检测间隔从 15 分钟缩短到 1 分钟，并配合合理的连接回收时间，可以有效避免因连接失效导致的 CommunicationsException 异常。关键是要让连接池的检测频率高于网络设备或数据库服务器断开空闲连接的频率。
